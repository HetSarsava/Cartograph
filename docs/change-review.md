# Review a Python patch with execution evidence

Cartograph connects a Git patch to changed functions, partial caller paths,
observed tests, and bounded mutation checks. It helps answer **“Do these tests
distinguish this behavior?”** It does not certify correctness or invent mutation
testing. No model or API key is needed.

## Run the demo

```bash
uv sync --extra dev
uv run cartograph review-demo --output logs/change-review-demo
```

Choose a new output directory each time; the command never deletes an existing
directory. It creates two explicitly synthetic Git repos and runs real pytest
processes. Open:

- `logs/change-review-demo/weak/.cartograph/review/report.html`
- `logs/change-review-demo/strong/.cartograph/review/report.html`

Both proposed patches correctly add discount subtraction. Both suites pass.
The weak test uses a zero discount, so changing subtraction to addition survives.
The strong test also checks a nonzero discount and detects that same mutation.
The demo demonstrates assertion sensitivity; it is not an upstream bug discovery.
The strong test was written explicitly, not generated by Cartograph.

## Review your own repo

Install the project's pytest dependencies in the same interpreter as Cartograph.
Provide the Git root (not a subdirectory) and a base commit or branch:

```bash
cartograph review --repo /path/to/project --base main
cartograph review --repo /path/to/project --base HEAD~1 \
  --test-path tests/unit --test-path tests/integration \
  --max-mutations 10 --timeout 60
```

The diff compares the base's tree with the current working tree, including staged,
unstaged and non-ignored new files. It is not the three-dot merge-base diff used by
some PR interfaces: supply the intended merge-base explicitly when needed.
Default test path is `tests`; repeat `--test-path` for other in-repo paths/node IDs.
Git and Python 3.12+ are required. Install with `uv sync` or `pip install -e .`.

Results default to `.cartograph/review/report.html` and `report.json`. Add
`.cartograph/` to your project's `.gitignore`. Each invocation preserves raw pytest
logs, commands, and per-test execution JSON under `.cartograph/review/runs/<id>/`.
The report includes a source digest and timestamp. Source shown in the report is
the reviewed snapshot, not a live editor. Caller paths are partial and bounded.
HTML is self-contained with escaped repository text; retain the adjacent JSON and
`runs` directory when sharing links to raw evidence. The complete report may
contain proprietary source and local paths; share deliberately.

`--output /outside/project/report` changes the report directory. Prefer the
default or an output outside the repository, so reports do not become new inputs.
`--max-mutations 0` collects execution evidence without executing mutations.
`--timeout` bounds each subprocess (baseline, selection control, and mutation),
not the entire review. At most `1 + 2 * max_mutations` pytest processes run;
controls are reused for identical test selections. The default mutation budget
is five. At most 500 candidates are listed; any truncation is explicit.

Exit codes: 0 = report generated, 2 = baseline unavailable/failed, 1 = command
error or a survivor with `--fail-on-survivor`. An incomplete report can exit 0;
inspect `status` and individual evidence before using this in CI.

## Evidence, not a safety score

| Label | Meaning |
|---|---|
| Baseline passed | At least one test passed; pytest exited 0 without collection/setup/teardown errors. Skips/xfails may still exist. |
| Detected | Tests observed executing the line passed an unmodified selection control, then at least one failed with the mutation. |
| Survived | The selected tests passed with the mutation. It may be equivalent, intentional, or insufficiently asserted. |
| Unexecuted | No baseline-passing test context was attributed to the mutation line. |
| Unstable control | Running the selected tests alone did not pass; no mutation credit is awarded. |
| Error / timeout | Inconclusive; never counted as detection. |
| Budget exhausted | Candidate was not checked. |
| Baseline unavailable | Mutation execution withheld because baseline was not usable. |

Report `complete` means the implemented checks finished, **not “safe to merge.”**
`incomplete` includes unmapped changes, unsupported operators, skipped files,
deletions, controls/process errors, source changes, or budget exhaustion. A
`baseline_failed` report cannot support any mutation result.

Coverage.py records executable line contexts. The report only displays changed
executable lines in the test table; blank/comment lines are not coverage gaps.
Module import and test collection happen outside test contexts. A changed `def`
or decorator can execute there without being attributed to a test. Setup and
teardown belong to the current pytest node ID. A session fixture is attributed
only to the test that actually executed its setup; this is not a complete fixture
dependency analysis. Skipped/xfail tests are not selected for mutation checks.

## Implementation and limits

- Tree-sitter maps changed new-side lines to the innermost function or method.
  The existing graph provides up to 30 resolved caller paths. Alias/dynamic
  resolution is partial; unknown edges remain unknown.
- Mutation operators: binary `+ ↔ -`, `== ↔ !=`, `< ↔ >=`, `<= ↔ >`, and
  `True ↔ False`. Only changed function lines are eligible. Comments, string
  contents, tests and `conftest.py` are not mutated. Every candidate must compile.
  This does not exercise every semantic effect of the patch.
- Tests execute in fresh disposable source copies assembled from tracked and
  non-ignored working files. The original checkout is never the pytest cwd or
  mutation target. Test dependencies are not installed by the command.
- Copies are not a security sandbox. Tests can still access the network, absolute
  paths, databases and environment credentials. Use this on trusted repositories.
  Ignored assets, submodules, editable dependencies outside the copy, generated
  artifacts and symlinks can prevent faithful reproduction. Missing baseline
  dependencies surface as errors.
- Serial pytest only. No xdist, subprocess coverage or exhaustive runtime
  dependency capture. The runner clears project `addopts` and inherited
  `PYTEST_ADDOPTS`, but keeps pytest configuration/fixtures and installed plugins.
  Use explicit `--test-path` selections; this controlled run does not replace CI.
- Selection controls reduce order-dependence mistakes but cannot eliminate flaky
  tests. There is no automatic regression-test generation or proof of equivalence.

## MCP

After generating a report in the default location, a configured Cartograph server
exposes `read_review_report()`. It returns the structured report and recalculates
`source_matches_current`. It neither runs tests nor mutates files and is available
without `--allow-execution`. Custom output directories are read through the CLI
artifacts instead. The other eight tools keep their existing behavior.

## Sources and prior art

- [Coverage.py contexts](https://coverage.readthedocs.io/en/latest/contexts.html):
  actual per-test execution attribution through `switch_context`.
- [pytest hook API](https://docs.pytest.org/en/stable/reference/reference.html):
  test protocol and outcome reporting.
- [mutmut](https://github.com/boxed/mutmut): existing mutation testing.
- [pytest-testmon](https://github.com/tarpas/pytest-testmon): existing affected-test selection.

Cartograph's contribution here is the focused patch report connecting these kinds
of evidence to its graph. No general speedup or first-of-its-kind claim is made.
